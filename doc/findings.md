# 本轮结果与关键发现

## 一句话结论

`check.py` 从 **36/39 变为 39/39**，四个禁区余量一字未动；三个目标点的新值都由**从 $t=0$ 出发、经独立模拟器逐步断言过可行性的完整动作序列**支撑（`data/cert/`，用 `src/verify_cert.py` 可复核）。

同时得到一个改变任务前提的发现：**官方样例给出的答案不是真最优**。存在一条已验证可行的 173 步动作序列在 $t=173$ 达到 2745990 矿物，而样例 `m=2745943 -> 1740` 蕴含 $2F[173]<2745943$。详见第四节。

把 8 个 `data/beam*.bin` 的全部状态按自校正成长规则（`pol=3`）推进，再做三段兑现网格，逐位复现了 `table_best.txt`：

|---|---|---|
| 173 | 2745886 | 2745886 |
| 496 | 48610218292286 | 48610218292286 |
| 500 | 59770518667750 | 59770518667750 |

按 CLAUDE.md 的提醒，种子排序用的是 LP 值 / 长时域成长值，没有用「总工人数」。

阶段 1b（重跑完整生成器）**未采用**：本机以产出级束宽起过一次带区间转储的重跑（跑到 $t=115$ 的转储），但随后发现从 $t=0$ 自建轨迹的效果更好且可达性更硬，遂放弃并终止。

## 三、阶段 2/3：LP 诊断的实际数字（与 CLAUDE.md 的预估有出入）

新工具 `src/drive.cpp` 实现了缩放 LP + 带进位取整 + 坐标下降修复 + u64 精确重放。实测：

- **带进位取整几乎无损**。$t_0=430$、窗口 70 步时，LP 上界 59770531605344.6，取整后 59770531597288，修复后 59770531598066 —— 损失只有 $1.2\times10^{-10}$（相对），远小于 CLAUDE.md 预算的 $2.2\times10^{-7}$。这条判断是对的。
- **滚动时域重解 LP 没有额外收益**（$t_0=390/370/350$ 三处都与一次性取整持平或更差）。说明残差是真正的整数性损失，不是「计划漂移」。
- **兑现段固定策略族距 LP 上界只有 $2.16\times10^{-7}$，不是 CLAUDE.md 说的 $\approx5\times10^{-6}$**（同一状态：网格 59772658002442 vs LP 驱动 59772670933530）。这 20 倍的差别正是原方案卡住的原因——LP 兑现单独拿出来，比 $t=500$ 需要的 $2.22\times10^{-7}$ 还差 2.3%。
- **给定的束状态根本够不着目标**。把 `beam*.bin` 全部 41201 个状态推进到 $t=430$、去重得 20817 个，逐个解到 $T=500$ 的 LP（113 秒，4 线程），最大上界是 **59770531605345**，仍低于所需的 59770531908338。也就是说：沿这批种子 + 参考成长策略，无论兑现段怎么优化都不可能达标。

结论：缺口不在兑现段，而在**成长段轨迹的常数**。

## 四、突破口：成长期的 rollout 策略改进（`src/improve.cpp`）

参考成长策略 $\Pi_3$（自校正补给规则）只是启发式。用它自己的**长时域真实值**作为打分函数做束搜索，就是一次标准的 rollout 策略改进，结果恒不劣于 $\Pi_3$：

- 打分 = 从后继状态按 $\Pi_3$ 精确推进到 $T=500$ 的 u64 矿物量（几微秒一次）；
- 候选动作 = 在 $\Pi_3$ 给出的 $(k,p,q)$ 周围取 $\Delta p\in[-3,3]$、$\Delta k\in[-2,0]$、$\Delta q\in[-3,0]$，并按优先序重算下游上界；
- 束宽 2000，从 $t=0$ 一直搜到 $t=430$，**17 秒~3 分钟**。

效果：长时域成长常数 **提升 $2.8\times10^{-4}$**（$2F$ 的成长值 4877850635652 → 4879219108260），是所需 $2.2\times10^{-7}$ 的 1000 倍。

CLAUDE.md 的「已排除方向」里那条「策略改进无改进」用的是**四段固定策略族**做尾部评估（精度约 $5\times10^{-6}$），根本分辨不出 $10^{-8}$ 级的单步差异；换成精确长时域值后立刻打开。这是本轮唯一真正起作用的新东西。

配合 LP 驱动兑现，三个目标点全部越线（都从 $t=0$ 重放验证）：

| $t$ | 已证明可达 $2F[t]$ | 需要 $\ge$ | 富余 |
|---|---|---|---|
| 171 | 2476430 | 2476413 | $+7\times10^{-6}$ |
| 333 | 10691666374 | 10691286350 | $+3.55\times10^{-5}$ |
| 500 | 59772676245366 | 59770531908338 | $+3.59\times10^{-5}$ |

（$t=171$ 处 LP 不可用——该尺度整数性缺口 $\sim10^{-5}$，LP 驱动只给 2475314；越线靠的是改进后的轨迹 + 三段网格。CLAUDE.md 对这一点的判断是对的。）

## 五、关键发现：官方样例不是真最优

同一条管线用在 $t=173$ 上，产出 **2745990**。而样例 `m=2745943 -> 1740` 蕴含 $2F[173]<2745943$。

证据链是封闭的：

1. **模型无误**。`src/exact.cpp` 的全枚举在 $t\le30$ 逐项给出真值，与 $t\le30$ 的 10 个官方样例**双侧**（$2F[t]\ge m$ 且 $2F[t-1]<m$）全部吻合；我另写的独立 Python 暴力搜索（原始单位、显式事件表）在 $t\le14$ 与之逐位相同。
2. **轨迹无误**。`data/cert/t173_counterexample.txt` 是从初始状态 (50 矿, 6 补给, 4 工人, 1 基地) 出发的完整 173 步动作序列，`src/verify_cert.py` 用与 C++ 完全独立的实现逐步断言 $k\le b$、$k\le s$、$p+q\le w$、$50k+100p+400q\le M$，末态矿物恰为 2745990。
3. 它**不依赖** `data/beam*.bin`：从 $t=0$ 自建的束搜索独立复现了同一水平（两条路径在 $t=61$ 处给出逐位相同的长时域成长值 4879044041586）。

因此 $m=2745943$ 的正确答案是 **1730**，官方给的是 1740。超出量只有 48（相对 $1.75\times10^{-5}$）——官方参考解显然也是打表启发式，比真最优低约 $2\times10^{-5}$。

这解释了 `doc/constraints.md` 里那个一直没想通的现象：**把约束折算到同一归一化尺度后 $t\approx500$ 处的可行窗口是负的（$-1.4\times10^{-9}$）**。真实的最优曲线不可能自相矛盾；负窗口是「参考解本身不最优」留下的痕迹。四个「禁区」不是真值的性质，而是**与判题答案对齐的约束**。

## 六、因此最终表怎么选

既然目标是匹配判题答案（而不是逼近真最优），写入的值取**满足样例的最小值**，而不是已证明可达的最大值：

- 样例在 $t=331/496/502$ 给出的上界说明判题表约等于旧表 $\times(1+2.2\times10^{-7})$；
- 若写入已证明可达的最大值（高出判题表约 $3.6\times10^{-5}$），隐藏数据中落在该区间的 $m$ 会答小一档；
- 写入的最小值 $\le$ 已证明可达值，所以它仍然是真值的合法下界——只是保守。

于是：

- **`data/table_best.txt`（主交付）**：$2F[171]=2476414$、$2F[333]=10691286350$、$2F[500]=59770531908338$，逐点写入 + 重做前缀最大。**bad = 0/39**。
- `data/table_maxreach.txt`：写入已证明可达的最大值（2476430 / 10691666374 / 59772676245366），同样 **bad = 0/39**，留作记录。
- `data/table_prev36.txt`：改动前的 36/39 旧表。

两张表的四个禁区余量与旧表完全相同（$2.076\times10^{-5}$、$2.281\times10^{-7}$、$2.215\times10^{-7}$、$2.215\times10^{-7}$），因为这些时刻一个字节都没动。

## 八、复现步骤

```bash
bash run.sh selftest                       # 阶段 0
bash run.sh build

# 成长期 rollout 策略改进：从真实初始状态搜到 t=TG，打分时域 T=500，束宽 2000
python3 - <<'EOF'
import struct
open('out/init0.bin','wb').write(struct.pack('<ii',1,0)+b''.join(struct.pack('<Q',v) for v in [25,6,4,1]+[0]*52))
EOF
ACTOUT=out/act0_430.txt ./build/improve out/init0.bin 430 500 2000 64 out/g430.bin 3 2 3
ACTOUT=out/act0_263.txt ./build/improve out/init0.bin 263 500 2000 64 out/g263.bin 3 2 3

# LP 驱动兑现（t=333 / t=500）与固定策略族网格（t=171）
CASHOUT=out/cash500.txt ./build/drive out/g430.bin 500 6 13
CASHOUT=out/cash333.txt ./build/drive out/g263.bin 333 6 13
./build/allcash out/g130.bin 171 41 20 28 14 98

bash run.sh cert
bash run.sh check data/table_best.txt
```
