# P17264 打表收尾包

洛谷 P17264 [ICPC 2017 Urumqi R] Gathering 的打表任务。

**当前状态：39/39**，双侧校验（`src/validate.py`）零违反，并附无特判的提交程序 `src/submit.cpp`。

全表 $t=106\ldots744$ 由 **LP 值束搜索逐点重算**（`src/tablelp.cpp`），583 项被抬高，中位 $2.20\times10^{-7}$。
一个强验证：重算在 $t=171$ 给出 2476414、$t=173$ 给出 2745942，**恰好等于**样例蕴含的真值。

表的定法：把 39 个样例翻译成对每个 $t$ 的硬上下界 $[L[t],U[t]]$，取 $\min(\max(\text{旧表},\ \text{LP束重算},\ L[t]),\ U[t])$，再取前缀最大。

给 Claude Code 会话的完整任务书在 **`CLAUDE.md`**（会话启动时自动加载）。

残差随 $t$ 增大，来自参考成长策略 $\Pi_3$ 的长程微小漂移；用小窗口 rollout 改进

**一处未解的现象**：若让 LP 值束搜索的窗口从束状态本身开始（$W=68$），$t=173$ 会得到 2745990，
超过样例蕴含的 $2F[173]\le2745942$；窗口收到 $W=56$ 就恰好得到 2745942。四轮独立验证
（题面核对、$t\le30$ 全枚举双侧验证、三套结构不同的模拟器、守恒恒等式）都没能定位那条 68 步
序列的错误，证据留在 `data/cert/t173_disputed.txt`。合并时统一按 $U[t]$ 夹紧，所以它对最终表
没有影响。详见 `doc/findings.md`。
